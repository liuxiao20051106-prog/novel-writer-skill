# 上下文预算与记忆打包

仅在长篇/连载、跨会话写作、批量生成，或诊断「AI 忘了前文设定」「前后矛盾」时读取。核心底线（不依赖聊天记忆；事实以项目文件为准；每次生成只喂本章真正需要的东西）已内置于 SKILL.md。

> 相关指南：台账与状态追踪的字段见[长篇连续性与项目记忆](project-continuity.md)与[连续性台账](../templates/continuity-ledger.md)；章节任务的写法见[章节任务卡](../templates/chapter-brief.md)；批量与跨会话的审批点见[AI 自动化工作流](automation-workflow.md)。

## 核心事实：AI 不记得

模型每次生成都是"新的一次性阅读"，它只看见**这次**喂进去的内容。所谓"AI 忘了第 3 章的设定"，本质是**你这次没喂**。所以长篇写作的真正工程问题是：**每次生成该喂什么、喂多少。**

## 每次生成的打包清单（按优先级）

必带（缺一就容易出事）：

1. **章节任务卡**：本章目标、阻力、转折、信息增减、章末状态、约束（见模板）。
2. **上一章结尾 800-1500 字**：衔接的来源，比摘要更可靠。
3. **上一章结果摘要**（3-5 句）：发生了什么变化、角色现在什么状态。
4. **相关角色卡**：只放本章出场的角色（姓名、目标、说话方式、当前状态、与他人的关系）。
5. **活跃伏笔与支线**：本章要碰的那些，带"埋设章/计划回收章"。
6. **风格锚**：开头三章的 200 字样本 + 禁用词表 + 目标句长。

按需：世界观中与本章相关的规则、时间线片段、术语表、已透露/未透露信息的边界。

**不要**每次塞进：全书大纲、全部角色、全部伏笔、历史章节全文。塞满不等于有效，反而稀释重点。

## 分层摘要（控制体积的关键）

| 层级 | 内容 | 长度 | 何时用 |
|------|------|------|--------|
| **全书摘要** | 主线、当前卷、主角状态、核心承诺 | ≤300 字 | 每次生成 |
| **卷摘要** | 本卷目标、关键转折、当前局势 | ≤200 字 | 卷内每次 |
| **章摘要** | 发生了什么、变了什么、留下什么 | ≤80 字/章 | 取最近 3-5 章 + 相关旧章 |

滚动更新：每写完一章，立刻更新章摘要；每 10 章重算一次卷摘要；每卷重算全书摘要。**摘要必须由人（或经人确认）过一遍**——AI 自己生成的摘要会累积偏差。

## 预算分配（经验区间，按模型上下文调整）

| 内容 | 占比 |
|------|------|
| 系统指令（SKILL.md + 风格锚） | 15-25% |
| 事实层（角色/设定/伏笔/时间线） | 20-30% |
| 前文（上一章结尾 + 近期摘要） | 20-30% |
| 本章任务卡与约束 | 10-15% |
| 留给生成与对话 | ≥20% |

留出余量：输出 2000-4000 字中文约占 3-6k tokens；上下文一旦逼近上限，先压缩事实层（删除不相关角色），而不是删前文。

## 两步生成法（防止大段跑偏）

1. **先出章节计划**：3-5 个关键事件、出场角色及其目标、情感起点→终点、要埋/要收的伏笔、章末状态。**人确认后再写正文。**
2. **按计划写正文**：计划被批准后，把计划本身作为"契约"一起喂给模型。

这一步能省掉"生成三千字才发现方向错了"的浪费，也是批量写作时唯一可靠的护栏。

## 记忆的三种载体（不要混）

| 载体 | 存什么 | 不存什么 |
|------|--------|----------|
| **项目文件（唯一事实源）** | 设定、角色状态、时间线、伏笔台账、已发生事实 | 灵感、临时想法 |
| **章节正文** | 成稿 | 计划与讨论 |
| **会话** | 过程中的取舍讨论 | 任何需要跨会话保留的事实 |

规则：会话里产生的**新事实**（新角色、新设定、新死亡、新关系），写完后必须回写项目文件，否则下一次会话它就不存在了。

## 防漂移的三条硬规矩

1. **风格锚随行**：每次生成都带同样 200 字样本；换模型时尤其要带（否则文风断裂）。
2. **同书尽量同模型**：中途换模型时，用前 3 章各 200 字做风格参考。
3. **生成后立刻回填**：新增事实、角色状态变化、时间线、伏笔变化——写进台账再进入下一章。

## 每卷一次的"设定审计"

长篇写到中后期，即使有台账也会积累边缘矛盾。建议每 10 万字（或每卷末）做一次：

1. 导出核心实体清单（角色、地点、道具、时间线、已透露的秘密）；
2. 让 AI 逐项对比检查：时间线是否自洽、年龄/距离是否算得过来、有没有已透露与未透露的越权；
3. 发现矛盾后：优先在后续剧情里自然"圆"回来（已发布章节改起来成本高），同时在台账中更正；
4. 检查活跃支线是否 ≤3 条，长期没推进的支线要么推进要么合并。

## 会话交接模板

新会话开头，先给 AI 三样东西，再提需求：

```
【本次任务】第 X 章：……（目标字数 / 必须推进 / 禁止改动）
【当前状态】全书摘要 + 上一章结尾 800 字 + 出场角色卡
【风格锚】样本 200 字 + 禁用词表 + 句长区间
```

收尾时要求 AI 回填：本章新增事实、角色状态变化、时间线变化、伏笔变化、与任务卡的偏差、待用户确认项。
